# 流批一体交接实验台（Stream/Batch Handoff Lab）

同一业务事件：**白天走流式汇总，夜间有完整批次补算**。接入服务、批处理器、指标查询端
作为**三个独立进程**分别运行。系统保证：

- 夜间批次结果**不会覆盖并丢掉**交接后新到的事件；
- 流批重叠的事件**不会被算两次**；
- 交接边界**可解释、可审计**（三元组落库）；
- 支持**迟到更正与删除**（带符号补偿 + 旧桶重锚）；
- 任何汇总差额都能**下钻追到具体事件**，而不是只看总数对不对。

全部数据由**随机生成器**产生，无任何硬编码期望值；正确性由随机化属性测试 + 三方对账保证。

---

## 1. 三个独立进程

| 进程 | 模块 | 端口 | 职责 |
|------|------|------|------|
| 接入服务 ingest | `app/ingest.py` | 8101 | **唯一**的事件写入口（新增/更正/删除），维护全局接入序号 |
| 批处理器 batch | `app/run_batch.py` | —（轮询共享库） | 常驻轮询，发现批次就逐桶交接；可暂停/注入故障/崩溃恢复 |
| 查询端 web | `app/web.py` | 8102 | 只读查询 + 控制面 + 静态网页；自身**绝不写业务事件**（经代理转发给 ingest） |

三者通过同一个 WAL 模式 SQLite 文件协作，所有写操作在短事务内完成，因此可以分别启停。

```bash
./start_all.sh        # 拉起三个进程，日志在 data/logs/，PID 在 data/run/
./stop_all.sh         # 停止
# 网页： http://127.0.0.1:8102/
```

## 2. 可解释的流批交接边界

每次批次运行在 `batch_runs` 表冻结一个**三元组边界**，网页和接口都直接展示这句话：

> 本批只接管【事件时间 < `watermark_event_time`】且【接入序号 ≤ `snapshot_ingest_seq`】
> 的未锚定贡献；之后新到事件的 `batch_id` 恒为 NULL，留在流式区，不会被覆盖。

- **水位（watermark）**：按小时桶对齐，只接管事件时间严格小于水位的桶；
- **快照序号（snapshot）**：批次启动瞬间冻结全局接入序号，只接管该序号之前的接入；
- **逐桶独立事务锚定**：每处理一个桶提交一次，锚点写入 `batch_anchors`，
  崩溃后凭锚点从下一个桶续算，已提交桶不重复。

### 为什么不会双算、不会丢新事件

每条业务贡献在 `ledger` 表有一行，带 `batch_id`：

- `batch_id IS NULL` → 仍由**流式侧**持有，计入 `stream_agg`；
- `batch_id = 某批次` → 已交接给**批处理侧**，计入 `batch_anchors`。

交接 = 把符合边界的 ledger 行的 `batch_id` 从 NULL **原子改为本批 id**，同时确定性重建
该桶的 `stream_agg`。一行贡献任一时刻只属于一侧，查询按 `batch_id` 分区求和，
重叠在结构上不可能发生。快照序号之后的新事件其 ledger 行永远是 NULL，旧批次无法回溯吸收。

## 3. 更正与删除 = 带符号补偿，支持迟到

`app/events.py` 把每个逻辑交易建模为版本链：

- **更正（upsert 新版本）**：先写一条旧金额的**反向冲销**（`reverse`，负 delta），
  再写新版本**正向贡献**（`forward`，正 delta）；
- **删除（delete）**：只写反向冲销，事件状态置 `deleted`；
- 所有 delta 落在**事件时间**所在的小时桶。因此迟到的更正/删除天然能落到已交接的旧桶。

已锚定桶出现迟到贡献时（`app/batch.py::reanchor_late`）：该桶整体重锚到一个新批次，
旧批次标记 `superseded`（历史保留可审计）。重锚只吸收当前序号以内的迟到行，
更晚的在线事件继续留在流式区——**冻结边界不可回溯**。

## 4. 两种交接方式的代价对比

系统同时实现了两种方案，可在网页或 `--mode` 切换：

| 维度 | **ledger 逐条贡献锚定（选定）** | replace 区间整体替换（对照） |
|------|-------------------------------|------------------------------|
| 交接动作 | ledger 行原地 UPDATE `batch_id` | 整桶重算后 DELETE+INSERT 快照 |
| 明细保留 | 每条贡献可追溯到 txn/版本/动作 | 只剩桶合计，**无法回答差额由哪笔交易造成** |
| 迟到更正成本 | 只动**实际涉及的贡献行** | 桶内**全部活跃事件**重算覆写，与更正数无关 |
| 写放大趋势 | 随更正涉及量增长 | 随桶内事件总量线性增长，热桶越热越亏 |
| 快照后新事件 | 天然隔离（batch_id 恒 NULL） | 必须额外用快照序号隔离，否则盲覆写丢事件 |

实测命令（统计真实写 DML 次数，数据全随机）：

```bash
python3 -m app.demo benchmark
```

## 5. 正确性怎么证明（不是只看总数）

### 三方独立重算逐桶逐维度比对 —— `app/reconcile.py`

- **路径 A 原始事实**：只信 `events` 表每个交易的最新版本状态，独立 SUM；
- **路径 B 逐条台账**：只信 `ledger` 带符号贡献求和；
- **路径 C 物化视图**：`stream_agg` + `batch_anchors`（replace 桶用「快照 + 迟到增量」）。

外加分区守恒不变量（未锚定贡献之和 = 流式物化；锚定贡献之和 = 锚点）与
replace 桶专属守恒。任何一方被篡改或丢行，都会在**具体的 (桶, 维度)** 上暴露差额。

### 差额下钻到事件

`trace_difference` 逐交易比较「events 中的应有净贡献」与「ledger 中的实际净贡献」，
直接列出对不上的 txn_id。实测：删掉一条 414102 的台账行后，对账立刻在
桶 158400 / 维度 M-001 报出差额 -414102，并精确指向交易 `T-C000`。

### 随机化属性测试 —— `app/test_random.py`

每个种子跑 60 步混合操作流（随机新增/更正/删除/交接/迟到），每一步都：

1. 跑三方对账；
2. 与一个**完全独立的 Python 参考模型**逐桶逐维度比对（不是比总数）；
3. 断言交接后新事件绝不被旧批次覆盖；
4. 最后武装故障跑崩溃恢复，断言最终仍全部一致且批次正确提交。

```bash
python3 -m app.test_random [种子...]      # 默认 5 个种子，可传任意多个
```

### 故意篡改演示

```bash
python3 -m app.demo tamper        # 篡改一条锚点 → 捕获差额 → 用 ledger 自动修复
```

## 6. 网页可做的事

打开 http://127.0.0.1:8102/ ：

- **切换查看交接前后 / 流批两侧明细**：逐条贡献表有「全部 / 仅流式 / 仅批处理」页签，
  可按桶、维度、交易号过滤；正向贡献绿色、反向冲销红色；
- **暂停批处理并继续在线输入**：点「暂停批处理」后仍可提交事件，恢复后可见
  快照之后的事件全部留在流式区、未被本批锚定；
- **模拟提交中断再恢复**：选择故障点（首批提交前 / 逐桶锚定中途）并武装，
  常驻 batch 进程崩溃（审计留痕）后自动从锚点恢复；`--once` 模式则以退出码 7 真实退出，
  重启同一命令即可恢复；
- **三方对账与差额下钻**、批次边界解释、逐桶锚点、版本链、审计日志实时可见。

## 7. CLI 演示场景（不依赖 HTTP，直接调同一套库逻辑）

```bash
python3 -m app.demo reset-demo     # 清库并随机生成一个白天的交易
python3 -m app.demo run-batch      # 夜间 ledger 交接（--mode replace 看对照方案）
python3 -m app.demo late           # 交接后注入迟到更正/删除，触发旧桶重锚
python3 -m app.demo pause-demo     # 暂停 → 在线输入 → 恢复，验证边界不回溯
python3 -m app.demo crash-demo     # 提交中断（退出码7）→ 重启恢复，验证幂等续算
python3 -m app.demo reconcile      # 三方对账
python3 -m app.demo tamper         # 篡改锚点 → 差额下钻 → 自动修复
python3 -m app.demo benchmark      # 两方案写放大对比
```

## 8. 目录结构

```
streambatch/
├── app/
│   ├── config.py        # 端口、桶大小、库路径
│   ├── store.py         # SQLite schema、连接、接入序号、审计
│   ├── events.py        # 事件版本链、带符号补偿（更正/删除）、接入事务
│   ├── batch.py         # 交接边界、逐桶锚定、replace 对照、迟到重锚、暂停/故障/恢复
│   ├── reconcile.py     # 三方重算、分区守恒、差额下钻
│   ├── query.py         # 查询端读路径（流批分区明细、边界解释）
│   ├── generator.py     # 随机虚构交易/更正/删除生成器
│   ├── ingest.py        # 接入服务进程（8101）
│   ├── web.py           # 查询端进程（8102，含同源代理）
│   ├── run_batch.py     # 批处理器进程入口
│   ├── demo.py          # CLI 演示场景
│   └── test_random.py   # 随机化正确性测试
├── static/index.html    # 单页实验台（无第三方依赖）
├── start_all.sh / stop_all.sh
└── README.md
```
